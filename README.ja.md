# KODAMA

**日本語学校・塾向けの学生カルテ／出欠管理システム**

[English →](README.md) ・ [中文 →](README.zh-CN.md)

2018年から2020年にかけてフレームワークを使わずPHPで一から書き上げ、実際の日本語学校で運用されていた
校務管理システムです。最大の特徴は、**校暦を人手で維持するのではなく、チェックインの実データから
逆算して推定する**という点にあります。

> [!WARNING]
> **本リポジトリは閲覧用のコードアーカイブです。公開ネットワーク上に配置しないでください。**
> 本アプリケーションには、認証を伴わないデータ操作エンドポイント、SQL インジェクション、
> 認証なしのファイルアップロード処理、反射型 XSS が存在します。設計とコードを「読む」ために
> 公開しているものであり、サービスとして稼働させることを想定していません。
> デモを試す場合は `127.0.0.1` にのみバインドし、破棄可能なデータで実行してください。
> 詳細は[既知の制約](#既知の制約)を参照してください。

## 概要

日本語学校・塾には、毎日発生してしかも手間のかかる業務が二つあります。

**出欠管理。** 単に出席したかどうかではなく、**コマ数**ベースでの出席率が求められます。
入管（出入国在留管理庁）は留学生の在留資格を審査する際にこの数字を確認します。
誤りがあれば、学生本人の在留に直接影響します。

**証明書の発行。** 在学証明書、卒業証明書、在留資格認定証明書交付申請書 ——
いずれも書式の決まった公的な様式で、それを手作業で、何度も埋めることになります。

KODAMA はこの二つを一つのシステムにまとめました。学生カルテを唯一の情報源とし、
出欠はチェックイン記録から自動集計され、証明書はカルテから直接 PDF として生成されます。

データベース設計からフロントエンドまで、コードはすべて一人で書きました。
フレームワークなし、Composer なし、PHP と jQuery と手書きの SQL のみです。
製品仕様とテストは同僚が担当しました。

## 特徴：チェックインデータから校暦を推定する

多くの出欠管理システムは、「どの日に授業があるか」を記した校暦をあらかじめ登録しておくことを
前提としています。しかし語学学校ではこれが現実的ではありません。振替授業、国民の祝日、
学校独自の休校日 —— 校暦の維持そのものが業務負担になり、しかも更新を一度忘れれば、
出席率がすべて狂います。

KODAMA は発想を逆にしました。**校暦を尋ねず、実際に誰がチェックインしたかだけを見ます。**

クラスごと・コマごとに、チェックイン人数と在籍人数の比率を評価します。

| チェックイン率 | 判定 | 根拠 |
|---|---|---|
| 0% | `休` 休校日 | 誰も来ていない → そもそも授業がなかった日 |
| 50% 超 | `出` 授業実施 | コマ数に算入し、出席率の計算対象とする |
| 0〜50% | `不` 不明 | 自動判定せず、担当者の確認待ちとしてフラグを立てる |

実装は [`attend/situation_class.php:109`](attend/situation_class.php#L109) にあります。

中間の帯域で**あえて推測しない**という判断が、この設計で最も気に入っている部分です。
この出席率は最終的に入管の目に触れる数字です。確信が持てないとき、システムは
「わからない」と言うべきであって、それらしく見える誤った数字を返すべきではありません。

チェックインの受付時間には前後の余裕を設定でき（`classtime` テーブルの
`aheadperiod` / `delayperiod`）、遅刻・早退の判定しきい値（`allowlate` / `allowearly`）も
学校ごとに調整できます。

## 機能

### 出欠管理

- **チェックイン画面** —— 個人用と集団用の2モード。加えて HTTP エンドポイントを備え、
  別端末からの打刻にも対応します（[`attend/AddAttendRecordGet.php`](attend/AddAttendRecordGet.php)）
- **月次出欠簿** —— 31日 × 1日あたり最大4コマの色分けマトリクス。
  「金曜1限は出席／欠席」というマス単位まで、学生1人分あるいはクラス1つ分の1か月を一画面で把握できます

  状態：`出` 出席 ・ `欠` 欠席 ・ `遅` 遅刻早退 ・ `公` 公欠 ・ `休` 休学 ・
  `帰` 一時帰国 ・ `-` 休校日 ・ `不` 不明
- **二系統の出席率** —— **コマ数**ベースと**日数**ベースを並行して算出します。
  入管はコマ数を見ますが、学校内部の管理は日数で回ります。遅刻早退は
  「その日は出席として数えるが、コマ数からは1コマ差し引く」扱いとしており、
  両者の数字が食い違うのはまさにこの処理によるものです
  （[`attend/getstudentmonthattand.php:205`](attend/getstudentmonthattand.php#L205)）
- **手動修正** —— 自動判定の結果は手作業で上書きできます。`manualmodified` フラグにより、
  人が介入した事実が記録として残ります
- **統計の全再構築** —— [`attend/situation_rebuildall.php`](attend/situation_rebuildall.php) により、
  生のチェックイン記録からすべての集計を再計算できます。判定ルールを変更しても後戻りできます

### 学生カルテ

学籍情報、在留資格情報（在留カード番号・パスポート・在留期限）、成績、面談記録、賞罰、
進路（進学・就職）、学費納入、作品 —— これらをテーブルに分けて保持します。
`student` に基本情報、`student2` に在留関係の項目を置いています。

### 証明書の PDF 生成

TCPDF を用い、実際の様式レイアウトに学生データを直接流し込みます。

| | |
|---|---|
| 在学証明書 | 卒業証明書 |
| 在籍証明書 | 卒業見込証明書 |
| 修了証明書 | 修了見込証明書 |
| 修了証書 | 卒業証書 |
| 退学証明書 | 推薦書 |
| 学業成績及び出席状況証明書 | 再入国承認に係る書類 |

そして最も手強いもの —— **在留資格認定証明書交付申請書**。複数ページにわたり、
項目数は優に100を超えます。

### 権限管理

管理者／教師／仲介の3ロールを `userrights` テーブルで制御します。
パスワード再設定は PHPMailer によるメール送信で行い、トークンは `token` テーブルに保存され
2日で失効します。

### インターフェース

日本語・中国語の二言語対応。複数のテーマカラーを選択でき、選択内容は cookie に保持されます。

## セットアップ

**動作環境：** PHP 7.4（PDO・GD 拡張が必要） ・ MySQL 5.7 以上 ・ Apache または Nginx

PHP 8 には**対応していません**。同梱の TCPDF 6.2.26 が、PHP 8.0 で削除された `$str{i}` 形式の
文字列オフセットを使用しているためです。対応するには、まず同梱ライブラリの更新が必要です。

```bash
git clone https://github.com/hera2019/kodama.git
```

**1. データベースを作成し、デモデータを投入する**

```bash
mysql -u root -p -e "CREATE DATABASE kodama_demo CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_520_ci;"
```

```bash
mysql -u root -p kodama_demo < db/kodama_demo.sql
```

**2. データベース接続を設定する**

```bash
cp config/config.example.php config/config.php
```

`config/config.php` を編集して接続情報を記入してください。
このファイルは `.gitignore` に登録済みで、コミットされることはありません。

**3. Web サーバのドキュメントルートをプロジェクト直下に向けてアクセスする**

デモ用アカウント：

| ユーザー名 | パスワード |
|---|---|
| `admin` | `kodama-demo` |

デモデータベースには2クラス・約30名の学生と、2019年8月から2020年2月にかけての
約1,000件のチェックイン記録が含まれています。出欠マトリクスと休校日の自動判定が
実際に機能する様子を確認するには十分な量です。
なお、そこに含まれる氏名・写真・連絡先はすべて架空またはプレースホルダーです。

## データモデル

全22テーブル。中核となるものは次のとおりです。

| テーブル | 役割 |
|---|---|
| `student` / `student2` | 学生の基本情報／在留資格関連項目 |
| `attendance` | 生のチェックイン記録。1日1行、最大4コマ分（`time11`〜`time42`） |
| `situationclass` | クラス・コマ単位の集計。休校日の判定結果を含む |
| `situationmonth` | 学生・月単位の集計。日ごとの状態を JSON で保持 |
| `classtime` | コマの時間割と遅刻・早退のしきい値 |
| `attendproperty` | 出欠状態のマスタ（出／欠／遅／公／休／帰／-／不） |
| `idconfig` | 汎用マスタ（国籍・在籍状態・コース・在留資格・進路ほか） |
| `studentdata` | 申請フォームの入力内容。JSON で保持 |
| `usermanage` / `userrights` | ユーザーと権限 |
| `operatelog` | 操作ログ |

## 既知の制約

2018年から2020年にかけて、独学で書き進めたコードです。今日の基準に照らせば明らかに不十分な点が
いくつもあり、一部は2019年当時の基準でもすでに不適切でした。隠さずここに列挙します。
実態以上に良く見せるアーカイブは、正直なアーカイブより価値がないと考えるためです。

### セキュリティ上の欠陥

冒頭の警告は、以下を根拠としています。

- **Ajax データエンドポイントに認証がありません。** `dataproc/*_proc.php` は学生・ユーザー・
  チェックイン・学校設定に対する参照／追加／更新／削除を提供しますが、6ファイルのいずれも
  セッションや権限を検査していません。URL に到達できる者は誰でも、学生情報やパスワードハッシュを
  読み取り、データを改変・削除できます。
- **SQL インジェクション。** 一部のクエリは `prepare()` に渡す**前**に文字列連結で組み立てられて
  おり、プリペアドステートメントは何も保護していません。`QueryStudent` の WHERE 句
  （`$sql .= $Param`）、`UpdateStudent` の SET 句、`DeleteStudent` の ID リストが該当します
  （いずれも [`dataproc/student_class.php`](dataproc/student_class.php)）。
- **認証なしのファイルアップロードで、保存先を呼び出し側が指定できます。**
  [`plugin/upload/upload.php`](plugin/upload/upload.php) は保存先ディレクトリをリクエストの
  `dir` パラメータから受け取り、`realpath()` による封じ込めを行わずにパスへ連結します。認証も
  ありません。許容される拡張子が広いこととあわせ、任意の場所へのファイル書き込みと
  パストラバーサルが成立します。
- **反射型 XSS。** [`page/info.php`](page/info.php) は `$_GET['title']` と `$_GET['info']` を
  エスケープせずに出力します。他の画面でもデータベースの内容を未エスケープで出力しています。
- **セッション固定。** [`user/signin.php`](user/signin.php) はユーザーが操作できる cookie の値を
  そのまま `session_id()` に渡し、ログイン成功後もセッション ID を再生成しません。セッション
  cookie には `HttpOnly`・`Secure`・`SameSite` のいずれも付与されていません。
- **認証情報の扱いが脆弱です。** パスワードは MySQL の `SHA()`、つまりソルトなしの SHA-1 で
  保存されています。「パスワードを記憶する」はパスワードを base64 でセッションに保持します。
  自動生成パスワードは `substr(md5(time()), 0, 8)`
  （[`user/resetpassword.php`](user/resetpassword.php)）であり、リクエスト時刻から推測可能です。
- **CSRF 対策がありません。** フォーム送信にトークンが付随しません。
- **デモ用管理者パスワードを本 README に公開**しており、デモ DB にも対応するハッシュが入っています。
  これはデモ用の資格情報であって、そのまま使い続けてよい初期値ではありません。

### 設計・保守上の制約

- **MyISAM を使用**しているため、外部キー制約もトランザクションもありません。テーブル間の
  整合性はアプリケーション側で担保しています。
- **データ層と表示層が分離されていません。** `dataproc/*_class.php` の中で SQL・業務ロジック・
  HTML の組み立てが同居しています。
- **自動テストがありません。** 最もテストを書く価値のあった出欠判定ロジックさえ、すべて手作業で
  検証していました。
- **依存ライブラリを手作業で `plugin/` と `style/` に配置**しており、バージョンは2019年当時の
  ままです。Composer も npm も使っていません。
  [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) を参照してください。
- **PHP 8 には対応していません**（セットアップの項を参照）。

いま作り直すなら、Laravel あるいは Slim ＋ Composer を選び、データベースは InnoDB に移して
外部キーを張り、すべてのエンドポイントをフレームワークの認証・認可の下に置き、テンプレート
エンジンによる既定のエスケープを効かせ、出欠判定ロジックは独立したテスト可能なドメイン
サービスとして切り出します。
